## 名字的来历

《中庸》讲做学问的五步：**博学之，审问之，慎思之，明辨之，笃行之**。

这不是文案，是产品流水线本身——取证（博学）、质询（审问）、推理（慎思）、
辩论与裁定（明辨）、给出行动（笃行）。产品叫「明辨」，取的是第四步：
**辨得清，才说得出。**

## 它解决什么问题

你在网上搜「这个理财项目是不是骗局」，会得到几十条互相矛盾的说法。
有的是营销号洗稿，有的是几年前的旧闻，有的干脆是同一篇稿子被三家网站转载。
你没有时间一条条点开核实——而这恰恰是唯一有用的事。

| 常见困境 | 明辨的做法 |
|---|---|
| 观点满天飞，不知道信谁 | 只认可核验的来源；每条结论绑定证据 ID，点一下就能看原文 |
| 模型张口就来，编出一个不存在的链接 | 模型引用的每个 URL 都真去访问一次，打不开的不计入证据强度 |
| 三个来源其实是同一篇稿子 | 按主域归一 + 文本雷同聚类，转载副本不算独立来源 |
| 「没搜到」被当成「不存在」 | 五种取证状态显式区分，没查到就写明查了什么、在哪查的 |
| 报告写得漂亮但经不起追问 | 质检门禁打回重做；额度用满仍有异议时按「带保留通过」出报告，异议原样附上 |
| 置信度就是一个拍脑袋的百分比 | 拆成基准率 + 每一项调整 + 最终区间；上下夹在 3%–97% |
| 「多智能体」只是七个进度条 | 返工、辩论、未解张力、红队反方都是可数的真实动作，不是配置项 |

## 三条不肯让步的规矩

### 1. 无证据不立论

论点强度由**代码**判定，不由模型自评：

```
没有证据                 → unsupported（不支持）
有反向证据且双方都成立     → contested（存在争议）
≥ 2 个独立主域            → strong（强，且标记为已交叉验证）
≥ 2 条同源证据            → moderate（中等）
仅 1 条                   → weak（弱）
```

绑不上证据的论点会被标成 `unsupported` 并计入质检失分。

### 2. 诚实降级

取证失败时返回的不是空数组，而是结构化的**缺口（Gap）**：查了哪些关键词、
在什么范围内查的、索引新鲜度、以及「没查到」这件事本身有多可信。

| 状态 | 含义 |
|---|---|
| `sourced` | 已取证，原文抓取成功 |
| `pending` | 检索中 |
| `retrieval_failed` | 链接打不开，可重试 |
| `no_support_found` | 检索通道正常，但确实零命中 |
| `not_searched` | 没检索，结论基于模型先验（会明确标出来） |

### 3. 一切可回放

每次运行都有完整 trace：哪个专家、在哪个阶段、看了哪些证据、做了什么判断、
花了多少毫秒。报告页旁边就是「决策回放」。立场从接题到定稿的每一步变化，
也单独记在「立场演变轨迹」里。

## 三路取证

```
                   ┌─ InfiniSynapse (deepseek-v4-pro)
                   │    引擎自身的 agent 循环，自主联网检索
   用户问题 ────────┤
                   ├─ 明辨泛检索通道
                   │    博查 Web Search（语义排序）+ 行情接口
                   │    不可用时退到搜狗 / 百度 / 360 HTML 抓取兜底
                   └─ 取证层专家分头补采
                        司法风控查判决处罚 · 官方公告查备案批复
                        社区口碑查投诉亲历 · 关联溯源查股东实控人
                                │
                                ▼
                        逐条访问核验 → 主域归一 → 可信度打分 → 雷同聚类
```

**为什么要拆专项：** 判决书、处罚决定、投诉记录这类材料，泛检索几乎捞不到——
热度高的正面内容会把它们挤出前排。不专门去找，报告就只剩「大家都在说的那一面」。
每条补采到的证据记在具体某位专家名下，[`/experts`](http://47.119.112.225/mingbian/experts)
里的出场数字就是这么来的。

**为什么可信度不让模型打分：** `credibility.py` 是一套纯规则（0–100）：
来源类型基础分、有无发布日期、时效、正文是否真的抓到……每一分的来历都会在 UI 上列出来。

| 层 | 席位 | 职责 |
|---|---|---|

除常驻三席外追加派遣……」。不是随机凑人头。

## 流水线：八节点 DAG

```
① 意图漏斗      拆问题、判领域、定档位
② 研判计划      派专家、列子问题、定检索策略
③ 博学 · 取证    三路并行取证 + 逐条访问核验
④ 审问 · 质询    可信度打分、雷同聚类、独立性检验
⑤ 慎思 · 推理    InfiniSynapse 加权推理与成文
⑥ 质检 · 门禁    规则 + LLM 五维打分 ──未过──┐
⑦ 明辨 · 辩论    门控评估 →（够分才）对抗辩论   │
⑧ 笃行 · 落地    行动清单、实体图谱、指标        │
                                              │
        ┌─────────────────────────────────────┘
        │ 证据不足 → 打回 ③ 补采
        └ 推理有问题 → 打回 ⑤ 重写
```

返工额度用满时分两种结果：

- **硬指标未达标** → 如实标「质检未达标」，未达标项写进报告
- **硬指标已达标，质检官仍有意见** → 「带保留通过」，异议原样附上

三个档位：

| 档位 | 角度 | 取证 | 返工 | 辩论额度 | 实测耗时 |
|---|---|---|---|---|---|
| 速判 | 4 | 6 条 | 0 轮 | 0 | 约 3 分半 |
| 深研 | 6 | 12 条 | 1 轮 | 1 | 约 7–9 分钟 |
| 专家 | 9 | 16 条 | 2 轮 | 2 | 约 12–15 分钟 |

首页六个示例卡是提前跑好的真实报告（含辩论与轨迹），点开零等待。

## 选择性辩论门控

辩论很贵（红队攻击 + 裁判裁定各打一次引擎），所以**不是每份报告都辩**。
先算六项分歧信号的加权分，够阈值才开辩；关掉的时候也要把判据写出来——
「这次没分歧」本身就是一条结论。

| 信号 | 权重 | 含义 |
|---|---|---|
| 论点存在对立证据 | 1.2 | 有论点同时挂着正反证据 |
| 存在未解张力 | 1.0 | 模型自己承认两派谈不拢 |
| 置信度落在灰区 | 1.0 | 概率落在 35%–65% |
| 立场与概率不自洽 | 1.4 | 给了明确方向，把握却不到一半 |
| 证据来源集中 | 0.8 | 独立来源过少或检出一致性团伙 |
| 弱论点占比偏高 | 0.8 | ≥34% 的论点为弱或无证据 |

高风险领域（反诈、公司尽调、健康传闻、加密资产、消费维权）阈值下调 0.6。
裁判单轮最多挪动 20 个百分点，防止一轮辩论掀翻结论。
辩论改动的概率会作为一条调整项写进置信度阶梯，可审计。

## 立场演变轨迹

从接题到定稿逐点留痕，每一步记录：立场、概率、证据量、独立来源数、绑定论点数，
以及相对上一步的变化类型：

| 变化 | 含义 |
|---|---|
| `init` | 研判起点，尚未取证 |
| `ground` | 首次落地或证据底座变厚 |
| `firm` | 方向不变，把握加强 |
| `soften` | 结论被削弱，把握下调 |
| `reverse` | 方向性掉头 |
| `hold` | 本步未改变结论 |

变化描述由代码对比相邻节点的数字差生成，不是模型事后编故事。

## 部署到服务器

遵循多项目隔离：独立目录 + venv + `mingbian.service`（本机 `127.0.0.1:8767`）
+ nginx `location /mingbian/`。不改动同机其它项目（如 Anker）。

在服务器项目目录内：

```bash
sudo bash deploy.sh
```

脚本会：同步代码（保留已有 `.env`）→ 建 venv 装依赖 → 写 systemd →
幂等插入 nginx → 健康检查。旧 `sinan.service`（同端口）会自动停用。

公网入口：

| URL | 说明 |
|---|---|
| http://47.119.112.225/mingbian/ | 研判台 |
| http://47.119.112.225/mingbian/api/health | 健康检查 |
| http://47.119.112.225/mingbian/ledger | 调用台账 |
| http://47.119.112.225/mingbian/bench | Benchmark |
| http://47.119.112.225/sinan/ | 旧路径 301 → `/mingbian/` |

本地用 expect 上传（密码走环境变量，不写进仓库）：

```bash
export MB_SSH_PASS='your-password'
./deploy/scp.exp ./ root@47.119.112.225:/opt/projects/mingbian-upload/
./deploy/ssh.exp 'cd /opt/projects/mingbian && sudo bash deploy.sh'
```

更稳妥的做法是在服务器上 `git pull` 后执行 `deploy.sh`，示例数据用
`scripts/seed_demos.py` 在服务器本地生成，或把 `data/demos/*.json` 单独同步上去。

## 数据契约

引擎成文时必须附带 `mb-meta` JSON 块，由代码解析并与证据池绑定。关键字段：

- `verdict` / `stance` / `dimensions`
- `base_rate` + `adjustments` → 合成最终概率与区间
- `evidence[]`（含可访问 URL、来源类型、发布时间、摘录）
- `claims[]`（绑定 `evidence` / `counter_evidence`）
- `entities[]` / `relations[]` / `tensions[]` / `redteam[]` / `gaps[]`
- `actions[]` / `triggers[]`（行动清单与「什么情况下要回来重判」）

报告落库后还会附上：`quality`、`debate`、`revision`、`trajectory`、
`trajectory_summary`、`experts`（含出场统计）、`trace`、`metrics`。
